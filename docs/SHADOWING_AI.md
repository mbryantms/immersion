# Local shadowing and optional AI assistance

This phase implements the recording portion of G05 and the structural/recovery portion of G08–G09. It retains React 19, TypeScript, Tailwind, Radix, TanStack Query, FastAPI and SQLite. It adds no speech model, remote recording endpoint, or new framework.

## Shadow and compare

The supported **Watch or listen** and **Clarify** steps of a guided scene offer **Listen to source**, **Record my voice**, **Stop and save take**, learner playback, download and removal. The source pauses when recording or learner playback starts. Listening to the source pauses learner playback. Recording is absent from reduced-support and check steps, preserving their answer-visibility contract.

Microphone permission is requested only after the learner selects Record. The browser's MediaRecorder uses a supported Opus/WebM or MP4 format, with browser fallback. A take is limited to 60 seconds and 8 MiB; the page finalizes recording when hidden or when SPA navigation leaves the recording surface. Tracks are released on success, error, cancellation and navigation. Permission granted after cancellation/navigation is immediately released. Stop before reloading: browser shutdown can interrupt asynchronous finalization.

Only a completed, nonempty take replaces the latest take for that exact source snapshot. IndexedDB keys include scene and item IDs, fingerprint, effective times, and every original line's ID, revision and Chinese text. Changing mutable scene progress does not detach the recording; a different source snapshot cannot silently inherit it. Empty, oversized, denied or cancelled captures preserve the previous take. An atomic IndexedDB put replaces the prior stored take only on success. If storage is blocked/unavailable/full, the current completed take remains playable/downloadable in the tab and the previous stored take remains. Removal has a recoverable error state. Blob URLs are revoked when replaced or unmounted.

Audio stays in this browser origin's IndexedDB; it is never uploaded or included in AI requests. A recording event contains only scene/fingerprint/duration metadata and `assessed: false`. It does not create pronunciation evidence or a grade. Clearing browser storage, changing origin or losing the browser profile can remove recordings; database backups do not include browser audio. Download important takes. One latest take per scene snapshot is the current scope; a recording library/multiple historical takes and full browser-data export/restore remain future work.

The learner compares syllables, rhythm and tone changes with the source. Recording, transcription confidence and successful playback do not establish pronunciation or tone accuracy. Validated assessment, targeted feedback and learning-outcome validation remain open. Microphone access requires a browser secure context: localhost or HTTPS. The existing plain HTTP hostname/Tailscale serving configuration does not by itself grant microphone access.

## AI generation and cache contracts

Settings has explicit **Allow AI generation** and **Prefetch explanations on word lookup** switches. Generation is available by default when the configured CLI exists; prefetch is **off by default**. A lookup with prefetch off does not start AI work. Opt-in prefetch requests only the core explanation, skips busy capacity, and cancels on item/policy changes. Selecting Explain requests core assistance; **Request more detail** separately requests examples/nuance/pronunciation notes. Core failure or closing the dialog cannot chain additional generation. Settings explains that the CLI may contact its configured remote service with source text and translation. Microphone audio never enters this path.

Core and extras use separate prompt-v4 artifacts and strict Pydantic response schemas: required fields, strict scalar types, forbidden unknown fields, bounded list/text sizes and nested shapes. The word breakdown must consume each indexed Chinese token exactly once, in order, using complete adjacent tokens. Split, omitted, duplicated, reordered or invented tokens fail validation. Particle entries must refer to present source text and cannot duplicate entries. Translation batches require an exact-length array of nonblank strings without coercing objects or numbers. The provider adapter bounds response/error output and handles invalid JSON/text as recoverable failures.

These checks establish structural consistency and token grounding, **not linguistic accuracy**. They cannot certify the translation, grammatical interpretation, sandhi/neutral-tone claims, contextual appropriateness, completeness of function-word explanations, or level of generated examples. Extra-example pinyin is a deterministic estimate. UI copy preserves this distinction. Source-word pinyin, dictionary definitions and HSK annotations are attached from local analysis after validation; the model cannot replace them with invented fields. Generated explanations do not contribute mastery evidence.

Cache identity includes original Chinese, English context, stored analysis/selected readings, model, prompt version and explicit retry generation. A source edit during generation discards the response and appends an audit event. Malformed output produces an audit diagnostic without caching or returning the raw response. Accepted/unreviewed valid caches remain readable without the CLI while AI assistance is enabled. Prompt-v3 artifacts remain in history and are bypassed by v4 rather than deleted.

## Reject and explicitly retry

Core and extra artifacts expose their own Reject action and optional reason. Rejection persists in `AiArtifact.accepted` and an audit event; it immediately hides that artifact and prevents future cache reuse for that context/generation. Reopening the sentence shows a rejection state with **Request another attempt**. Regeneration is explicit, preserves the original rejected artifact, verifies the current source context, and advances a context-specific generation setting. SQLite writer serialization and UUID replay protect against duplicate/ambiguous retries. Separate retries of the same rejected generation coalesce rather than skipping multiple generations. A rejected artifact for an older corrected source cannot reset the current cache.

No new database migration is needed: policy/generation counters use Setting, feedback/retry/discard diagnostics use Event, and immutable AI responses use existing AiArtifact. Browser recording storage has its own version-1 schema and is separate from SQLite.

## Resource and cancellation boundaries

Each explanation uses a UUID request ID. Abort, dialog close, source revision changes, item navigation and best-effort page-hide cancellation notify the API; a short bounded tombstone handles cancellation arriving before its POST. Queued/single-flight waits poll cancellation, and the running adapter terminates only its own process group. Queue capacity is six waiters, total registered requests twelve, queue wait thirty seconds, response/error output 256 kB each, explicit generation timeout 180 seconds and adapter timeout at most 600 seconds. Errors report unavailable, busy, cancelled, changed source, rejected artifact, invalid schema, timeout or provider failure without exposing provider stderr.

An API priority gate favors waiting explicit requests over background work and skips speculative work when busy. Interactive requests cancel API prefetches. A shared POSIX file lock serializes API and worker provider execution for the same data directory, removing the old process-only lock's API/worker overlap. The lock/adapter follows the repository's Linux/systemd deployment; native Windows support is unverified. Disabling generation cancels API-scoped requests and prevents new translation batches. A worker batch already running in another process can finish. Priority does not preempt active worker generation, cancellation registries are process-local, and full worker job budgets/cross-process scheduling remain open. Browser termination/network loss can prevent cancellation delivery; bounded server timeouts remain the fallback. No real provider authentication or remote request was exercised in this delivery.

## Verification and remaining gates

Combined checks: **216 backend tests, 27 frontend unit tests, 53 Chromium browser checks**, TypeScript/Vite production build, changed application Python/new-test core correctness lint and whitespace checks. Backend tests cover strict/adversarial schema/token/translation cases, no malformed cache, source-edit races, offline cache, persisted rejection, idempotent retry generations, policy, cancel-before-POST, queued/running cancellation, priority, shared locking with a separate worker process, timeout and oversized stdout/stderr. Fake executables replace the actual provider.

Browser checks cover permission only on action, late grants, denial/cancel/empty/oversized capture, local persistence/reload/download/delete, quota recovery retaining the previous stored take, SPA microphone release, explicit extras, failed-core/close cancellation, rejection/reopen/regenerate, default-off prefetch and opt-in. A separate check uses Chromium's actual MediaRecorder with a generated local oscillator stream, then reloads and decodes/plays its saved recording. This validates browser encoding/storage/playback without claiming microphone hardware or spoken-Mandarin accuracy. A source-binding unit test checks identity changes versus mutable progress.

The production UI has passing WCAG-tagged axe scans for recording and explanations, along with mobile overflow checks. Inspection caught and fixed the explanation dialog's low-contrast secondary text. [Mobile shadowing](screenshots/shadowing-mobile.png) and [explanation review](screenshots/explanation-review.png) were visually inspected using synthetic fixtures. Automated scans are not full WCAG certification. Real microphone hardware, Safari/iPad codecs/permissions, manual screen-reader/200% zoom, source-audio comparison on personal media and validated pronunciation feedback remain unverified. No personal database or running deployment was changed.
